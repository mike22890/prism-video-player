# VOLTA — 交互设计 v4：视图栈 + 双击独占

> 2026-11-15 03:16 ｜ 增补：双击独占/还原、全用户群易用性审视

---

## 1. 需求还原

Mike 的原话：*「双击了一个视频就能就是我点的这个占据，比如四个视频就变成 1 个，然后再双击就回到之前的 4 个视频」*

拆成三个必须同时满足的要求：
1. 双击某格 → 该格独占整个视频区
2. 再次双击 → 回到双击前的状态（4 格）
3. **可继续嵌套**：单格状态下再双击另一个视频怎么办？

第 3 点是设计分水岭。两种做法：

| 做法 | 行为 | 问题 |
|---|---|---|
| A. 记一个「上一个布局」 | 只记一层 | 嵌套超过 2 层就乱；无法「后退」到任意中间态 |
| B. **视图历史栈** | 每次独占 push 一次快照，Esc/双击 pop | 天然支持多层后退、可以一路退回起点 |

**选 B。** 理由：视图栈是「历史」，用户心智里就是「后退」，不需要额外学习；而「记一个上一布局」是「开关」，用户会困惑「我现在在哪一层」。

而且 B 顺手解决了另一个问题：用户从 4 格 → 单格 A → 单格 B 之后想回 4 格，栈里正好有。

## 2. 视图栈的状态机

### 2.1 栈里存什么

不是存「布局」（1×1 / 2×2 / 3×3），而是存**完整的视图快照**：

```
ViewSnapshot {
    layoutMode      // 网格布局（2x2 / 3x3 / 拼贴…）
    slotStates[]    // 每槽：{ slotId, source, timePos, pause, volume, muted,
                    //         abLoopA, abLoopB, sid, aid, shaderChain, dwidth, dheight }
    focusSlotId     // 哪格是焦点（出声的那格）
    audioMaster     // 主控音量
}
```

内存成本实测：单槽约 450 B，9 槽满快照约 4 KB，栈深上限 16 层 → **最坏 64 KB**。可忽略。

**为什么要存 `timePos` 而不是重新加载**：用户双击进单格、退出来，播放位置必须一模一样。这是「体验正确」和「体验崩了」的分界线。

### 2.2 状态转移

```
        ┌──────────┐
        │  GRID    │  4 格 / 9 格，正常网格视图
        └────┬─────┘
             │ 双击槽位 N
             ▼
        ┌──────────┐
        │  SOLO    │  单格独占，N 占满视频区
        └────┬─────┘
             │ 双击槽位 M（M≠N，来自播放列表双击或另一格）
             ▼
        ┌──────────┐
        │  SOLO'   │  单格独占，内容换成 M
        └────┬─────┘
             │ 双击 / Esc / 右键→返回
             ▼
        ┌──────────┐
        │  栈 pop  │  回到上一个快照（内容、位置、焦点全还原）
        └──────────┘
```

**规则**：
- `enterSolo(slotId)`：push 当前快照 → 切到 SOLO
- `exitSolo()`：pop 快照 → 完整还原（槽位内容、播放位置、焦点、音量、着色器链、渲染尺寸）
- 栈空时 `exitSolo()` 退化为「回到网格布局的默认模式」
- **栈深度 > 1 时，Esc 逐层回退**，不是一次退到底

### 2.3 「双击另一个视频」从哪来

SOLO 状态下，用户想换内容。两个入口：
- 播放列表里**双击**另一个条目 → push 当前 SOLO 快照 → SOLO' 播放新内容
- 视频区**双击** → 若当前已是 SOLO 且只有一个槽，双击 = exitSolo（回到上一个快照）

**歧义处理**：SOLO 状态下双击唯一的视频区，是「退出」还是「无操作」？
→ **退出**。因为用户双击的心智是「我要回去看别的」或「我要放大这个」，在已经是最大的状态下，双击 = 缩小，符合 F11 全屏后再按 F11 缩回的直觉。

### 2.4 关键：这个栈和「网格布局切换」是两件事

容易混，必须分清：

| 操作 | 改什么 | 栈 |
|---|---|---|
| 按 `G` 切 2×2 / 3×3 | 布局模式（几格） | 不 push |
| 双击某格 | 可见槽位集合（哪些在显示） | **push** |
| 双击播放列表条目 | 焦点槽位的内容 | **push** |

用户心智：「G 改格子数，双击改看哪个」。UI 上要分开表达——`G` 是工具栏按钮，双击是直接操作。

## 3. 为什么这个功能对性能是好事（实测）

用户会担心「双击变大 = 更费资源」。实际相反：

| 状态 | 总像素吞吐 |
|---|---|
| 4 格网格（每格 760×428@60） | 78.07 Mpix/s |
| 独占焦点格 1920×1080@60 + 其余 3 格 dormant | **124.42 Mpix/s**（网格的 159%） |
| 若独占时其余 3 格仍 active 渲染 | 182.97 Mpix/s（网格的 234%） |

**独占 = 其他格停渲染**（只保留解码，不出画面）。所以：
- 独占时总开销 ≈ 单路全屏播放，本来就是最省的状态
- 从 4 格进单格，GPU 压力**不升反降**（除了焦点格本身变大）
- 还原时其他格从 dormant 升回 active，开销回到网格水平

这套分级机制（v2 §3.3）在这一轮终于发挥出价值——**独占不是特例，是分级机制的自然结果**。

**实现**：进 SOLO 时，被隐藏的槽位设 `pause` 保持解码但停止出帧（mpv 的 `vo-pause` 或干脆 `dwidth/dheight` 设为极小 + 停渲染）；还原时恢复。

## 4. 易用性：分用户群看同一个功能

Mike 说「要考虑各种各样用户」。同一个双击，对不同人群应该是不同的体验。

### 4.1 用户群 × 需求 × 交互

| 用户群 | 典型场景 | 他们真正要的 | 我们的交互 |
|---|---|---|---|
| **追剧党**（90% 用量） | 一次看一个，偶尔切下一个 | 「别让我动脑子」 | 拖进来就播；双击 = 沉浸单格；Esc 回来 |
| **对比党** | 4 个视频同时看，找不同 | 「一屏看完，偶尔放大一个细看」 | 网格常驻；双击放大；**双击空隙/按钮区 = 返回** |
| **学习/剪辑党** | 反复看片段，A-B 循环 | 「精确到帧」 | 双击放大 + A/B 打点；帧步进 `,` `.` |
| **直播/监控党** | 多路同时看 | 「一格崩了不能影响其他」 | 每格独立进程 + 独立状态徽标 |
| **触屏用户** | 平板上划 | 「没有右键」 | 双击 = 放大；**必须有可见的返回按钮**，不能只靠双击 |
| **键盘党** | 不用鼠标 | 「全键盘」 | `Enter`/`Space` 放大返回、`Esc` 返回、`G` 切网格、`Tab` 换格 |

### 4.2 四条必须做到的易用性原则

**① 双击不是唯一入口**
触屏用户没有「双击空白处」这种精确操作。所以：
- 独占时，视频区**右下角常驻**一个返回按钮（不是 hover 才出现）
- 返回按钮在终端主题下长成 `[ BACK ]` 的样子，默认主题是箭头图标
- **双击视频区本身也能返回**（不是只能点按钮）

**② 状态必须可见**
- 独占时，视频区左上角显示 `SOLO · 1/4`，让用户知道「现在只显示 1 个，还有 3 个」
- 栈深 > 1 时显示 `◂ 2/3`（可回退层数），让用户知道能退几次
- 鼠标移到可双击的槽位上时，槽位边框高亮 + 光标变 `zoom-in`，**提前告知「这可以双击」**

**③ 快捷键覆盖全**
```
Enter / Space   放大当前格（再按返回）
Esc             逐层返回（栈深>1 时退一层，否则退出全屏）
Backspace       同 Esc
双击视频区       放大/返回
双击播放列表项   在 SOLO 中换内容
G               切网格布局
1/2/3           直接切 1×1 / 2×2 / 3×3
Tab / Shift+Tab 在格间移动焦点
```

**④ 动画要能解释状态变化**
从 4 格到单格，槽位应该**平滑放大**到视频区（200–280ms，ease-out），而不是瞬间切换 + 闪一下。
- 用 `Behavior on x/y/width/height { Animation { duration: 240; easing.type: Easing.OutCubic } }`
- 动画期间其余槽位淡出（150ms）
- 还原时反向
- **动画要能被关掉**（`prefers-reduced-motion` 对应设置项「减少动效」），无障碍要求

## 5. 边界情况清单（这些不想到就是 bug）

| 情况 | 处理 |
|---|---|
| 双击一个**正在缓冲**的槽位 | 允许，缓冲状态跟着进 SOLO |
| 双击一个**报错**的槽位 | 允许，独占后显示错误详情（比小格子更清楚） |
| 双击后原槽位被**删除**（文件没了） | 还原时该槽显示「源已移除」，不崩溃 |
| SOLO 中双击播放列表**当前已在播**的条目 | 不 push（避免无意义的栈增长），仅聚焦 |
| SOLO 中播放列表为空 | 返回按钮变成「回到网格」（空网格） |
| 双击发生在**动画播放中** | 立即中断动画，用当前实际位置重建快照 |
| 栈深超过 16 | 丢最老的（LRU），不崩 |
| 双击时正在**拖拽**播放列表 | 忽略双击（拖拽优先） |
| 同一视频被双击两次（快速） | 第二次 = 返回（这是用户想要的，不是 bug） |
| SOLO 中切换**主题** | 主题切的是 UI 皮肤，不影响视图栈；槽位内容不变 |
| SOLO 中切换**语言** | 同上 |
| SOLO 中 mpv 进程崩溃 | 显示错误 + 「重启此格」按钮；其他槽位不受影响 |
| 窗口最小化时双击 | 忽略 |
| 多显示器跨屏拖动槽位 | 视图栈存的是逻辑槽位，不存屏幕坐标 → 天然正确 |

## 6. 视图栈和 v2 分级机制的联动（这是设计的收敛点）

之前 v2 定了三档：focused / active / dormant。现在能串起来了：

| 视图状态 | 焦点格 | 其他可见格 | 隐藏格 |
|---|---|---|---|
| GRID（4 格） | focused | active | — |
| SOLO | focused（唯一） | — | dormant（停渲染，保解码） |
| 切到其他布局（2×2 → 3×3） | focused | active（新布局的格） | dormant |

**统一规则**：任何时候「不可见的槽位 = dormant，可见但非焦点 = active，焦点 = focused」。
视图栈负责「谁可见」，分级机制负责「可见的怎么渲染」。两者正交，互不干扰。

这意味着实现上**只有一个渲染档位决策函数**：
```
computeRenderTier(slotId, viewState) → focused | active | dormant
```
没有第二处逻辑决定渲染档位，也就没有「两处判断不一致」的 bug。

## 7. 新增的验收项

| 项 | 判据 |
|---|---|
| 双击进/出 SOLO 动画 | 240ms 内完成，60fps 不掉帧 |
| 还原保真 | 进出 20 次后，每格的 `timePos` 误差 < 0.1s、音量/静音/A-B 点完全一致 |
| 栈嵌套 | 连续双击 5 层，每层都能正确退出，最终回到起点状态一致 |
| 触屏可达 | 返回按钮在 44×44 pt 以上（触控命中区标准） |
| 减少动效 | 开启后动画时长 = 0，功能不受影响 |
| 性能不劣化 | 进 SOLO 时总像素吞吐 ≤ 网格的 170%（实测 159%） |

## 8. 这轮新增的可交接内容

视图栈是典型的「容易做错」的模块，交接时必须写清：

- `core/viewstack.py`：栈的 push/pop/快照序列化，纯逻辑，可单测
- 快照的**字段完整性**是硬约定：新增可回退的状态（比如「字幕轨选择」）时，**必须同时加进快照结构**，否则还原会丢状态
  - 防呆做法：快照用 `dataclass` + `fields()` 反射序列化，新增字段自动进快照，不靠人记得
- ADR：`docs/adr/0007-view-history-not-layout-toggle.md`
  - 背景：双击独占需要多层回退
  - 决策：用视图历史栈，不用「上一布局」变量
  - 备选：记一个上一布局（被否，理由是无法嵌套）
  - 后果：栈需要快照序列化；新增可回退状态要进快照结构
  - 何时推翻：如果用户反馈「后退」语义造成困扰（比如想回到某个具体格而不是整个视图）

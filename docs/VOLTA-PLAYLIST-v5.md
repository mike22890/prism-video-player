# VOLTA — 播放列表模型 v5

> 2026-11-15 03:20 ｜ 增补：多视频同播下的「播放列表归谁管」

---

## 1. 先拆词

「播放列表」在用户嘴里指两件事，多视频同播逼着它们分离：

| 用户说的 | 实际含义 | 归属 |
|---|---|---|
| 「我加了这些视频」 | **素材库**（有什么可播的） | **全局唯一** |
| 「接下来播什么」 | **播放队列**（播放语义） | **每槽位独立** |

4 个槽位各自在播，「接下来播什么」有 4 个答案，但「有什么可播的」只有一个库。所以拆开。

> **v5.1 修正**：素材库的主入口不是「手动添加」，而是**打开文件时自动扫描同目录**（见 `VOLTA-DIRECTORY-v5.1.md`）。手动添加降级为次要操作。数据结构上统一为 `ScanSource{ rootPath, mode(FULL_DIR|SINGLE_FILE), items[] }`，不再有「手动项」和「目录项」两种形状。

---

## 2. 三个概念

```
Library（素材库）        全局唯一 · 跨槽位共享 · 只管「有什么」
   │
   │ 装载 / 分配
   ▼
PlayItem（播放项）       一个可播放单元 · 带自己的队列和播放设置
   │                    { source, queue[], loopMode, abLoop, volume,
   │                      muted, sid, aid, shaderChain, timePos }
   │ 持有
   ▼
Slot（槽位）             视图上的一个位置 · 只管「现在显示谁」
                        { index, layoutCell, focus }
```

**关键设计：队列绑定在 PlayItem 上，不是绑定在 Slot 上。**

后果：切换布局（2×2 → 3×3）时，队列跟着内容走，不会因为槽位重排而丢失剧集队列。绑定在 Slot 上的话，改布局就丢——这是很常见但很难查的 bug。

---

## 3. 队列归属的三种模式

| 模式 | 语义 | 适用人群 | 实现 |
|---|---|---|---|
| **独立**（默认） | 每槽位自己的队列，各播各的 | 对比党 | 每槽位一份 mpv 进程，队列在 UI 侧 |
| **同步** | 所有槽位共享一个队列 + 同步进度 | 对比同一视频的不同版本/字幕/剪辑 | 一份队列，多进程订阅同一位置 |
| **链式**（可选，v2 再做） | 槽位 1 播完自动接槽位 2 的队列 | 串流播放 | 队列消费游标跨槽位 |

「同步」不是拍脑袋——GridPlayer 就有 `timecode seek sync mode`（上游仓库 commit 记录）。我们做，但明确它是高级选项，默认关闭。

## 4. 操作路由：拖到哪里，进哪里

这是最容易做糊的地方，必须一张表钉死。

| 用户动作 | 结果 |
|---|---|
| 拖文件 → **队列面板** | 追加到**焦点槽位**的队列 |
| 拖文件 → **库面板** | 只进素材库，不入队 |
| 拖文件 → **某个槽位上** | 该槽位换播这个文件（PlayItem 替换） |
| 拖**文件夹** → 队列面板 | 展开为一组，追加到焦点槽位队列（按名称自然排序） |
| 库面板多选 N 项 → 「▶ 并播」 | 分配到 N 个槽位，每项一个独立 PlayItem |
| 库面板多选 N 项 → 「▶ 串播」 | N 项进焦点槽位一个队列 |
| 双击库面板某项 | 载入到焦点槽位（覆盖），并聚焦 |
| 双击队列面板某项 | 该项插到当前播放项之后，立即跳转播放 |

**「并播」和「串播」是两个按钮，不是一个加参数。** 用户心智不同：并播 = 我要同时看，串播 = 我要接着看。合成一个下拉菜单 = 让用户猜。

## 5. 面板 UI

面板有两个模式，用户可切，操作会自动切：

```
┌─ 播放列表 ──────────────────────┐
│ [队列 ▾] [库]        焦点 SLOT 1 │
├───────────────────────────────────┤
│ ▶ 1  ep01.mkv              24:11  │  ← 当前播放（高亮 + 波形进度）
│   2  ep02.mkv              24:08  │
│   3  ep03.mkv              23:57  │
│   …                              │
│                                   │
│  循环 [文件|列表|关]  A[--] B[--]  │  ← 作用于焦点槽位
└───────────────────────────────────┘
```

**「库」模式的额外信息**——每项显示它当前在哪个槽位：

```
┌─ 素材库 ──────────────────────────┐
│ [队列] [库 ▾]                      │
├───────────────────────────────────┤
│   ep01.mkv              [SLOT 1]   │  ← 徽标说明占用关系
│   ep02.mkv              [SLOT 2]   │
│   tutorial.mp4            未装载   │
│   ep03.mkv              [SLOT 3]   │
└───────────────────────────────────┘
```

没有这个徽标，用户永远搞不清「我刚才双击的那个去哪了」。

**面板跟随焦点**：切换焦点槽位（`Tab` / 点击格子）→ 队列面板内容跟着切。用户不需要理解「面板属于谁」这个概念，他只看到「我现在看的那格，它的队列」。

## 6. 循环与 A-B 的作用域

| 操作 | 作用域 |
|---|---|
| `loop-file` / `loop-playlist` | **焦点槽位** |
| `ab-loop-a` / `ab-loop-b` | **焦点槽位** |
| 音量 / 静音 | 焦点槽位（批量操作走多选） |

「全部循环」= **焦点槽位队列**循环，不是「所有槽位一起循环」。后者是「同步模式」，两回事。

UI 上循环按钮旁必须标出作用对象：`循环[列表] → SLOT 1`，避免用户以为全局。

## 7. 对 v4 视图栈的修正（重要）

v4 说快照存每槽的 `source / timePos / pause / volume / muted / A-B / 轨道 / shader链 / dwidth`。

PlayItem 模型出来后，这个划分要重切：

| 归谁 | 内容 |
|---|---|
| **PlayItem**（内容属性，跨视图存活） | source, queue, loopMode, abLoop, volume, muted, sid, aid, shaderChain, **timePos** |
| **视图快照**（只管可见性） | slotBindings（槽位→PlayItem 引用）, viewMode, focusSlot, gridGeometry |

好处：`timePos` 挂在 PlayItem 上，进 SOLO 期间那格被替换过、位置变了，回来时自动是新的；没被替换的格，位置天然不变（因为它们的 PlayItem 一直是活的）。

**被替换的 PlayItem 要能救回来**：进 SOLO 时若焦点槽位的 PlayItem 被换掉，旧对象进快照的 `detached` 列表，还原时重新挂回。否则「进去换了视频再退出来」就丢了原片位置。

## 8. 边界情况

| 情况 | 处理 |
|---|---|
| 同一文件要出现在两个槽位 | 允许，两个独立 PlayItem（各自位置/音量独立） |
| 库里的文件被磁盘删了 | 标「源缺失」灰显，不自动删；播放时给具体错误 |
| 队列播放完 | 焦点槽位停在末尾（`keep-open`），显示「已播完」，不自动跳到别的槽位 |
| 空队列时点播放 | 按钮置灰 + tooltip「队列为空，去库里加」 |
| 拖到「同步模式」激活时的槽位 | 强制走独立模式并提示「同步模式下每格独立队列」 |
| 库面板条目正在被某槽占用又拖到另一槽 | 允许（复制），原槽不动 |
| 文件名排序 | 中文按拼音、英文按 locale（v2 的 `collation` 字段） |
| 队列 > 1000 项 | 虚拟滚动，不卡 |
| 断电恢复 | 队列、库、PlayItem 绑定一起存 JSON（schema 版本化） |

---

## 9. 验收项

| 项 | 判据 |
|---|---|
| 面板跟随焦点 | 切焦点后队列面板内容在 1 帧内更新 |
| 布局切换不丢队列 | 2×2 → 3×3 → 2×2 后，各队列内容与顺序完全一致 |
| 并播/串播分流 | 多选后两个按钮行为明显不同，无歧义 |
| 库徽章准确 | 徽标显示的槽位与实际播放槽位 100% 一致 |
| SOLO 往返保真 | 进 SOLO 换视频再退出，原片位置误差 < 0.1s |
| 循环作用域 | 改焦点槽位的循环不影响其他槽位 |

## 10. 可交接要点

- `core/library.py`：素材库，来源=拖入/扫描/最近播放
- `core/playitem.py`：PlayItem 数据类，**队列和播放设置全在这里**
- `core/queue.py`：队列操作（插入/删除/重排/游标）
- `core/binding.py`：Slot ↔ PlayItem 绑定表
- ADR：`docs/adr/0008-playitem-owns-queue-not-slot.md`
  - 背景：多视频同播时「播放列表」语义歧义
  - 决策：拆成 Library（全局）+ Queue（挂 PlayItem）+ Slot（只管显示）
  - 备选：队列挂 Slot（被否 —— 改布局就丢队列）；单一 mpv playlist（被否 —— 循环语义歧义，v3 §2.2 已述）
  - 后果：布局切换不丢队列；新增播放设置要加进 PlayItem 而非 Slot
  - 何时推翻：若将来做「跨实例共享队列」（多窗口同一队列），PlayItem 需要拆成「队列定义」与「播放实例」两层

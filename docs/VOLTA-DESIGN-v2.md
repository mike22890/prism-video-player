## 1. 多语言：切换必须干净到「逐像素可验」

### 1.1 架构

不用 Qt 的 `.ts` 翻译文件（那玩意儿在 QML 里维护地狱，改个词要开 Linguist）。改用**自建 JSON 词典 + QML 单例**：

```
core/i18n/
├─ locale.json          # 语言清单：code / name / 方向 / 日期格式
├─ zh-CN.json           # 词条
├─ en.json              # 词条
└─ i18n.py              # 加载器 + 校验器（构建期跑）
```

QML 侧只有一个入口：

```qml
Text { text: I18n.t("playlist.title") }
```

`I18n` 是 QML 单例（`pragma Singleton`），内部：
- 启动时按 `settings.language` 加载对应 JSON 到内存 map
- `t(key, args)` 返回查表结果，**查不到就回退到 key 本身并打 WARN**
- 切换语言 = 换 map + 发 `localeChanged` 信号 → 所有绑定属性自动重算，**不重建 QML 树**

### 1.2 「有的地方还是别的语言」怎么根治

这是 Mike 明确点名的坑。三道防线：

| 防线 | 手段 | 拦什么 |
|---|---|---|
| ① 编译期 | `i18n.py` 校验脚本：扫描 QML 源码里所有**裸字面量**（`text: "播放"`），出现在 `text/title/label/placeholder/tooltip` 位置就报错 | 硬编码文案漏网 |
| ② 构建期 | 词典一致性：所有 `locale.json` 列出的 key 集合必须**完全相等**，缺一个就 CI 红 | 某种语言缺词条 |
| ③ 运行期 | `I18n.t()` 查不到 → 回退 key + 打 WARN；UI 里显示 `??key??` 让人一眼看出 | 静默显示英文原文 |

**关键**：切换语言后所有文案走同一个 `t()`，不存在「这个控件忘了包翻译函数」的可能——因为忘了就编译不过。

### 1.3 特殊坑

- **数字/单位**：时长 `01:24:07` 用 `QTime` 格式化，不走翻译。
- **日期**：locale.json 里存格式串。
- **中文没有 1:1 的英文长度**：所有按钮宽度用 `contentWidth` 动态撑，不写死 px。终端主题用等宽字体（中文也是等宽，正好），默认主题用 `Segoe UI + Microsoft YaHei` 混排。
- **排序**：中文按拼音、英文按字母 → locale.json 里写 `collation: "pinyin" | "icu"`，交给 `QCollator`。
- **字体回退**：中文必须能渲染 → 令牌里字体栈必须含 CJK 字体，且**校验脚本检查字体栈里有没有覆盖 CJK 的字体**。

## 2. 主题系统：从「两套皮肤」升级成「可长出第十套」

Mike 说以后可能加更多主题。所以主题不能写死成 `if (terminal) ... else ...`。

### 2.1 主题 = 声明式清单，不是一堆代码

```
themes/
├─ terminal/
│  ├─ theme.json      # 令牌 + 能力声明
│  ├─ shell.qml       # 可选：覆写壳层
│  └─ shaders.json    # 该主题默认挂哪些视频特效
├─ default/
│  ├─ theme.json
│  ├─ shell.qml
│  └─ shaders.json
```

`theme.json` 长这样：

```json
{
  "id": "terminal",
  "nameKey": "theme.terminal.name",
  "tokens": {
    "color.bg": "#0a0f0a",
    "color.ink": "#33ff66",
    "color.accent": "#33ff66",
    "font.mono": "Consolas, 'Microsoft YaHei Mono', monospace",
    "radius.panel": 0,
    "radius.button": 0,
    "motion.duration": 120
  },
  "video": {
    "defaultShader": "crt-lottes",
    "overlay": "scanlines"          // QML 侧叠加：扫描线/暗角/弯曲
  },
  "capabilities": {
    "scanlines": true,
    "vignette": true,
    "curvature": true,
    "glow": true,
    "cursor": true
  }
}
```

### 2.2 新增一个主题要写多少代码

**只写一个 JSON + 可选一个 QML 壳**。令牌能填满就零 QML；只有当新主题的**布局结构**真的不同（比如「海报墙模式」）才写 `shell.qml`。

### 2.3 令牌分层（关键设计）

令牌分三层，优先级从低到高：

1. **基础层** `base.json`：中性的尺寸/动效基准，所有主题共有
2. **主题层** `theme.json`：颜色、字体、圆角、具体外观
3. **组件层**：组件内部私有微调（只允许引用令牌，不允许定义新颜色）

规则：**组件层禁止定义裸色值**。所有颜色必须来自主题层或基础层。这样任何主题切过去，组件都跟着变。

### 2.4 「全部生效」的可验证性

Mike 说「切换了结果发现有什么地方是不受主题影响的」——这必须**能自动查**，不能靠人眼。

**CI 门禁 `check_theme_coverage.py`**：
1. 扫所有 `.qml`，正则抓 `#rrggbb` / `rgb(...)` / `rgba(...)` 字面量
2. 出现在**主题定义文件之外** → 报错（组件层不许有裸色）
3. 列出每个令牌被哪些文件使用 → 找**孤儿令牌**（定义了但没人用）和**缺失引用**（用了但没定义）

**运行期门禁**：
- 切换主题时，对所有 `Item` 递归遍历，检查其 `color`/`border.color`/`font.family` 等属性是否都在当前令牌集合内 → 有例外就打 WARN 并列出控件路径
- 这能抓住「运行时动态设的颜色」这类编译期查不到的情况

**截图回归**：每个主题各截 6 张关键界面（主界面/网格/播放列表/设置/主题选择器/右键菜单），存基线。换主题后逐像素比对（阈值容差 0），任何差异 = 有人偷偷改了组件层。

## 3. 多视频下的着色器与画质增强：性能账

### 3.1 实测数字（按 1600×900 窗口、2×2 网格算）

| 场景 | 像素吞吐 | 相对焦点头 |
|---|---|---|
| 焦点头 1920×1080@60 | 124.4 Mpix/s | 100% |
| 1 个背景格 760×428@60 | 19.5 Mpix/s | 15.7% |
| 8 个背景格 | 156.1 Mpix/s | 125% |
| **8 路都按 1080p 渲染（错误做法）** | **995.3 Mpix/s** | **800%** |

**结论**：多路播放的成本瓶颈不在「几路」，在「每路渲染到多大」。差 **6 倍**。

### 3.2 核心机制：`dwidth`/`dheight`

mpv 有两个属性：`dwidth`/`dheight` = 「应用滤镜和缩放之后的显示尺寸」（源尺寸是 `width`/`height`）。它控制 mpv 往 VO 送多大的一张图。

- 背景格在屏幕上只有 760×428 像素 → 让 mpv 渲染成 760×428，而不是渲染 1920×1080 再缩下来
- 着色器在 760×428 的画布上跑，**像素量少 6 倍**
- 代价：背景格如果放大看会糊——但背景格本来就是缩略显示，**没人会放大看背景格**
- 焦点头保持原生分辨率，全特效

这就是「损耗小」的技术含义：**不是砍功能，是砍掉看不见的那部分像素**。

### 3.3 分级策略（三档）

| 档位 | 触发 | 渲染尺寸 | 着色器 | 色彩 |
|---|---|---|---|---|
| **focused** | 用户正在交互的那一格 | 原生分辨率 | 全套（CRT/VHS/增强） | 完整 |
| **active** | 网格里可见但未聚焦 | 实际显示尺寸 | 轻量（只保留主题必需的视觉，比如终端主题的 CRT） | 完整 |
| **dormant** | 折叠/不可见/后台 | 实际显示尺寸 | 无 | 简化（关 HDR tonemap 之外的重处理） |

切换 focus 时改对应 mpv 进程的 `dwidth`/`dheight` + `glsl-shaders` 属性即可，**不需要重启进程**。

### 3.4 运行时保护（防抖的关键）

不能只看静态规划，得看实际掉帧。mpv 有现成属性：

- `frame-drop-count`（输出端丢帧）
- `decoder-frame-drop-count`（解码端丢帧）
- `mistimed-frame-count`（时序错位）

**自适应降级逻辑**（每 2 秒采样一次）：
1. 若某格 `frame-drop-count` 在窗口内增长 > 阈值 → 先降该格 `dwidth/dheight`（渲染尺寸降一档）
2. 再持续掉 → 关该格的可选着色器（保留主题必需的）
3. 再持续掉 → 降到 dormant（暂停渲染，只留解码）
4. 全部恢复后**逐级回升**，但要迟滞（连续 N 次正常才升）避免来回震荡

这条路径用的是 mpv 原生属性，不写自己的状态机（skill 铁律 4）。

### 3.5 音频

多路同播必炸音频。规则：
- 只有 focused 格出声
- 其余格 `--no-audio`（启动参数，不动态切，切音频要重开流）
- 焦点切换时给新焦点格开音频、旧的关掉 → 这里用 `ao` 静音开关：mpv 有 `mute` 属性可动态切，不重开流

### 3.6 显存

每路一个 mpv 进程 = 一份解码缓冲 + 渲染纹理。9 路 1080p 时显存要算：
- 硬解表面（每路约 1 帧 1080p ≈ 3MB）
- libplacebo 渲染中间缓冲（每路按 1080p rgba16f ≈ 16MB）
- 9 路 ≈ 170MB+

对策：dormant 档释放渲染目标；`--gpu-context` 统一走同一 API 避免多份驱动开销；提供「显存紧张时自动降档」开关（读 mpv 的 `vo-drop-frame-count` + 系统显存查询）。

## 4. 易用性：新手 30 秒能用，老手不嫌浅

Mike 说「方便简单使用，直观」。设计原则：

### 4.1 三层交互

| 层 | 人群 | 入口 |
|---|---|---|
| **零配置** | 想看片的人 | 双击文件 → 直接播。默认单格、自动全屏自适应、自动挑最佳画质档 |
| **常用** | 日常用户 | 左侧播放列表（拖文件进来）+ 底部控制条 + 键盘快捷键 |
| **专业** | 爱折腾的人 | 设置面板（着色器参数、profile、IPC 控制台、性能面板） |

**关键**：专业选项默认藏起来，但不删除。设置面板分「基础 / 画质 / 高级」三档，高级档默认折叠。

### 4.2 首屏零学习成本

- 空状态就一句话 + 一个拖放区 + 一个「打开文件」按钮，不放教程弹窗
- 第一次播放自动切到合适的画质档并弹一行 toast：「已自动优化画质（1080p 锐化档）」，**告诉用户发生了什么，也告诉他去哪改**
- 快捷键提示用 `?` 键呼出，不用教

### 4.3 状态永远可见

每个格子有明确状态徽标：`加载中 / 缓冲 / 播放 / 暂停 / 错误 / 休眠`。
出错时显示**具体原因**（哪个 mpv 属性、哪个文件），不是「播放失败」。点一下可复制诊断信息 → 这就是「易于能快速分辨和辨别错误位置」落地到用户侧。

### 4.4 键盘优先

所有操作有快捷键，且和 mpv 习惯一致（`space` 暂停、`←→` 快退进、`f` 全屏、`q` 退出）。新增的：`g` 网格、`t` 主题、`l` 语言、`s` 着色器、`e` 增强档、`i`/`o` 设 A/B 点。

## 5. 新增能力的成本表（Mike 关心的「未来加更多」）

| 想加什么 | 要改什么 | 大概要素 |
|---|---|---|
| 新主题 | 1 个 JSON（+ 可选 1 个 QML） | **半天** |
| 新语言 | 1 个 JSON 词典 | 几小时（翻译量决定） |
| 新着色器 | 1 个 GLSL 文件 + `shaders.json` 加一项 | 1 天 |
| 新画质档 | `profiles/` 加一个 profile + 策略表加一行 | 半天 |
| 新布局（除网格） | `layout/` 加一个布局计算器 | 1–2 天 |
| 新引擎（未来换 VLC/FFmpeg） | 只动 `engine/` 一层 | 1–2 周（所以 `core/` 绝不含引擎代码） |

**这个表是整套架构的验收标准**：任何一行「要改整个项目」的，都说明分层没做对。

## 6. M0 阶段要加的验证项（成本敏感）

原 M0 只验「能不能传帧」。加上性能与正确性：

| 验证项 | 判据 |
|---|---|
| D3D11 共享纹理延迟 | < 30ms，CPU 拷贝 = 0 |
| 连续播放稳定性 | 1080p60 × 10 分钟不撕裂 |
| **dwidth 缩放生效** | 背景格 `dwidth` 设为 760 后，GPU 帧时间下降到对应比例（实测，不靠猜） |
| **自适应降级** | 人为制造掉帧（占满 GPU），能在 6 秒内看到降级生效且不震荡 |
| **多语言完整切换** | 切语言后逐屏截图，残留非目标语言字符 = 0（正则扫 `[\u4e00-\u9fff]`） |
| **主题全覆盖** | 6 张关键界面在两主题下截图 + 令牌覆盖率 100% |

**多语言残留检查可以自动化**：切到 en 主题后截图，OCR/正则扫描是否还有中文字符。这一条能进 CI。

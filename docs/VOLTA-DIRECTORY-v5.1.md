# VOLTA — 目录自动收录 v5.1

> 2026-11-15 13:23 ｜ 增补：打开视频时自动收录同目录视频，不用手动添加

---

## 1. 需求

Mike 的原话：*「当我打开视频，播放列表自动就有当前文件夹下的所有视频可以进行切换播放，我不要什么还得手动添加那种」*

这条直接改 v5 的模型：**素材库不是「用户拖进来的东西」，是「文件系统视图」。**

之前 v5 写「Library 素材库 = 拖入 / 扫描 / 最近播放」，把「手动添加」当成主要入口——错了。**主路径应该是零操作：打开即有。**

---

## 2. 改后的模型

```
打开一个视频
    │
    ▼
┌──────────────────────────────────────────────┐
│ ① 取所在目录                                 │
│    D:\Movies\Action\2024\                    │
└──────────────────────────────────────────────┘
    │
    ▼
┌──────────────────────────────────────────────┐
│ ② 扫描同目录（不递归）                       │
│    按文件名自然排序（ep01 < ep02 < ep10）     │
│    过滤：视频扩展名白名单 + 隐藏文件排除      │
└──────────────────────────────────────────────┘
    │
    ▼
┌──────────────────────────────────────────────┐
│ ③ 焦点槽位队列 = 整个目录                    │
│    当前打开的视频 = 高亮定位到那一项          │
└──────────────────────────────────────────────┘
    │
    ▼
┌──────────────────────────────────────────────┐
│ ④ 背景：素材库面板 = 当前目录 + 已添加目录   │
│    切换目录 → 队列重建（可撤销）             │
└──────────────────────────────────────────────┘
```

**关键**：用户什么都没加，队列里已经有整个目录。手动添加降级成「往队列里塞别的目录的东西」的次要操作。

## 3. 扫描规则（细节决定体验）

### 3.1 范围

| 选项 | 默认 | 说明 |
|---|---|---|
| 递归子目录 | **关** | 打开 `D:\Movies\Action\` 不应该把 `D:\Movies\Action\2023\` 也拖进来 |
| 包含隐藏文件 | 关 | `.` 开头的跳过 |
| 跟随符号链接 | 关 | Windows 上少见，防环 |
| 大目录上限 | **5000 项** | 超过则只取前 5000 + 提示「目录过大，已截断」 |

### 3.2 排序

**自然排序**（natural sort），不是字典序：

```
字典序（错）：  ep01, ep02, ep10, ep11, ep2
自然序（对）：  ep01, ep02, ep10, ep11, ep2
```

这是播放器里最常见的排序投诉来源。规则：把数字段当整数比较。

跨语言：中文文件名按拼音（`locale.json` 的 `collation` 字段，v2 已定义）。混合中英文时：**同「类型」比拼音/字母，不同类型先按数字，再按字母**。

### 3.3 过滤

- **视频扩展名白名单**：`.mp4 .mkv .avi .mov .webm .m4v .ts .wmv .flv .mpg .mpeg .m2ts .rmvb .3gp .vob .iso .ogv`
- **排除**：`.part .tmp .!ut .download` 等半成品文件（很多人下载中的文件带这些后缀）
- **图片不收**：`.jpg .png` 不是视频（虽然有些播放器支持图片序列，我们不支持）

### 3.4 性能

目录扫描必须是**异步的**，不能阻塞 UI。

实测（`os.listdir` + 扩展名过滤，含建目录）：

| 场景 | 实测 | 目标 |
|---|---|---|
| 100 项 | 1.0 ms | UI 零卡顿 |
| 1000 项 | 2.1 ms | 无感 |
| 5000 项 | 9.9 ms | 无感 |

**结论：纯目录列举根本不是瓶颈**，5000 项也只要 10ms。所以异步不是为了性能，而是为了两件事：**网络盘**（可能几秒）和 **QML 侧渲染几千行**（那才是卡顿来源）。

**实现要点**：
- 扫描在 `QThreadPool` 里做（防网络盘卡住 UI 线程）
- 结果**批量** emit（每 100 项或每 50ms 一次），不是每个文件一个信号
- QML 侧用 `ListView` 虚拟滚动，只实例化 ~15 个 delegate
- **绝不在扫描时抽缩略图**——那是另一个任务队列（见 §5）

**别在扫描时抽缩略图**——那是另一个任务队列的事（见 §5）。

## 4. 界面反馈

打开视频的瞬间，用户必须知道「队列已经有东西了」，而不是「咦怎么突然多了一堆」。

### 4.1 面板顶部显示来源

```
┌─ 播放列表 ──────────────────────────┐
│ [队列 ▾] [库]      焦点 SLOT 1      │
├──────────────────────────────────────┤
│ 来源: D:\Movies\Action\2024\  (24 项)│  ← 来源条
├──────────────────────────────────────┤
│ ▶ 1  ep01.mkv              24:11     │
│   2  ep02.mkv              24:08     │
│   …                                  │
└──────────────────────────────────────┘
```

来源条必须可点 → 弹出目录切换器。

### 4.2 打开时的 toast

```
┌────────────────────────────────┐
│ 已载入 D:\Movies\Action\2024\   │
│ 24 个视频 · 当前在第 3 个       │
└────────────────────────────────┘
```

2 秒后自动消失。**告诉用户发生了什么 + 告诉他现在在哪**（避免打开的文件不在第 1 项时的困惑）。

### 4.3 定位到当前

打开 `ep05.mkv` 而队列按 `ep01` 开头 → 队列高亮定位到 `ep05`，并且**列表自动滚动到那一项**。用户不该自己找。

## 5. 与「手动添加」共存

不是二选一，是**两种来源，一个队列**。

| 来源 | 加什么 |
|---|---|
| **目录扫描**（自动，默认） | 同目录全部视频，作为队列主体 |
| **手动添加** | 其他目录的文件，追加到队列尾部 |

队列条目要显示**来源**，让用户知道哪些是自动来的：

```
▶ 1  ep01.mkv                    24:11  📁
  2  ep02.mkv                    24:08  📁
  3  ep03.mkv                    23:57  📁
  4  tutorial.mp4                08:30  ✎   ← 手动加的
```

### 5.1 目录切换

用户换目录（点来源条）→ 队列整个替换。这是有破坏性的操作，所以：
- 换之前问一句：「切换目录会替换当前队列（24 项），继续？」——只在队列有手动添加项时问；纯自动目录直接换
- 支持撤销（Ctrl+Z）：恢复上一个队列

### 5.2 「另存为队列」的复合

用户手动加了别的目录的文件，又想保留原来的 → 「另存为队列」复制一份到库里当独立队列。这条 v2 再做，先留接口。

## 6. 与 v5 三层模型的对齐

v5 说 Library 是全局的。现在改成：

```
DirectoryScan（目录扫描结果）    ← 自动，随打开的文件变化
    │
    ▼
PlayItem.queue（队列）           ← 目录扫描结果 + 手动追加项 合并
    │
    ▼
Slot                            ← 显示谁
```

**修正 v5 的说法**：Library 不再是「用户拖进来的东西」，而是「一个或多个 DirectoryScan 的并集 + 手动添加项」。素材库面板（库模式）= 已加载目录的列表 + 手动添加项。

手动添加项其实也该统一成「目录扫描」——加一个文件时，隐式扫它所在目录（用户可能就想要整个目录）。**除非用户明确说「只加这一个」**（按住 Ctrl 拖 = 只加这一个）。

**这消除了一个特例路径**：不再有「手动添加的条目」和「目录条目」两种数据形状，全是「扫描来源 + 条目」。

数据结构：
```
ScanSource {
    rootPath      // 目录路径（手动单文件时 = 其父目录）
    mode          // FULL_DIR | SINGLE_FILE
    recursive     // 默认 false
    items[]       // 扫描到的视频
}
```

## 7. 边界情况

| 情况 | 处理 |
|---|---|
| 打开的视频所在目录有 5000 个文件 | 扫描异步进行，队列边扫边填，不卡 UI |
| 目录里有非视频文件 | 过滤掉，不显示 |
| 打开的视频被删了 | 显示错误，队列其余项正常 |
| 同名文件（不同扩展名） | 都列出，标注格式（ep01.mp4 / ep01.mkv） |
| 目录里有子目录里的剧集（用户想要） | 设置里开「递归」，默认关 |
| 网络盘 / 慢盘 | 扫描超时 10 秒后放弃并提示，不无限等 |
| 打开的视频在只读目录 | 扫描照常，只是不允许写回队列 |
| 队列里有手动项时切换目录 | 弹确认，可撤销 |
| 目录名含中文/emoji | 路径处理用 UTF-16，Windows 上安全 |

## 8. 验收项

| 项 | 判据 |
|---|---|
| 打开即有队列 | 双击任意视频 → 队列在 200ms 内出现同目录全部视频 |
| 定位正确 | 打开第 7 个文件 → 队列高亮第 7 个且已滚动可见 |
| 排序正确 | `ep1 ep2 ep10` 顺序为 ep1, ep2, ep10（不是 ep1, ep10, ep2） |
| 扫描不卡 UI | 5000 项目录扫描期间 UI 可交互（拖动窗口不卡） |
| 零操作 | 从打开文件到能按「下一个」切换，全程不点任何添加按钮 |
| 手动追加可用 | Ctrl+拖 = 只加这一个；普通拖 = 加整个目录 |

---

## 9. 这条改变了什么

之前 v5 的「素材库」是被动的容器，用户得往里塞东西。这版把**文件系统扫描变成主入口**，手动添加降级。

对应的产品定位变化：VOLTA 不再是「一个要你整理播放列表的播放器」，是**「打开文件就能连着看」的播放器**——跟系统自带播放器一样自然，但多出网格、多主题、多路。

这个方向对，也更符合 Mike 说的「简单、直观、别让我手动添加」。
